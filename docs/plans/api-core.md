Owner: `apps/api/` except `torch/agents/`. Status lives in `docs/STATUS.md`; this file records the judgment calls.

## 0. Environment blocker (read first)

The S1 session has no package index: `pypi.org` and `files.pythonhosted.org` answer 403 at the egress proxy, and fetching
sources another way was refused. Installed system-wide are only `pydantic 2.13`, `starlette`, `uvicorn`, `sse-starlette`,
`pytest`, `python-dateutil`, plus `ruff` and `mypy` binaries. **FastAPI, typer, structlog, pydantic-settings, hypothesis,
orjson and anthropic (and SQLModel/SQLAlchemy) are not installable here.** `uv sync` cannot run; there is no `uv.lock`.

What that means for what shipped:
- Everything rule-bearing is pure Python + pydantic and is **tested here** (system `python3 -m pytest`): domain, clock,
  calendar, world, adjudication, seed + reconciliation, scheduler, read models, and every API behaviour through the service
  layer (`torch/api/services/*`).
- Routers (`torch/api/routers/*`), the app factory, SSE and the typer CLI are thin wrappers over those services, written
  against FastAPI/typer and checked by ruff + mypy only. Their tests (`tests/test_api_contract.py`, hypothesis property test)
  `importorskip` and run wherever `uv sync` works.
- `structlog` and `pydantic-settings` are used when importable; `torch/log.py` and `torch/config.py` fall back to stdlib so
  pure modules run anywhere.
- `openapi.snapshot.json` is generated by `uv run torch openapi` — FastAPI's document when installed, else the same paths
  built from the contract table `torch/api/contract.py` and the same pydantic component schemas. A test asserts the app's
  routes equal the table, so the two cannot drift.

## 2. Interface for torch.agents (and the coordinator's adapters)

- **Tables** (`torch/domain/entities.py`, stored by `torch.db.store.Store`): `Run` (+`steps[]`), `RunEvent` (SSE log), `Evidence`,
  `Rule`, `RuleChange`, `RuleProposal`, `InboxItem`, `AuditEvent`, `Job`, `Hold`, `WorldCallLog`, `RunCheckpoint`, `LlmCall`,
  `PayerClaim` (world-internal). Fields follow the revised 01-domain-model (Run.mode/planner/situation_key/plan/usage,
  RunStep.progress_lines/policy_verdict, Evidence.suspicious/gathered_by, Rule.version/origin, Practice.agents_paused*).
- **Jobs**: `torch.scheduler.registry.registry.register(kind, handler)`; handler `(JobContext) -> JobOutcome | None`, sync or
  async; `ctx.enqueue(kind, due_at, payload, key)`. Kinds the world/API enqueue for agents (`torch/scheduler/kinds.py`):
  `run.start {run_id, inbox_item_id?|claim_id?}`, `claim.rejected {claim_id, code}`, `era.arrived {remittance_id}`,
  `claim.status_check_due {claim_id, n}`, `visit.checked_out {visit_id, appointment_id}`, `hold.escalate {hold_id, threshold_days}`,
  `eligibility.sweep {for_date}`. Next status check: `torch.scheduler.cadence.next_status_check(sent_on, after)`.
- **World** (`torch.world.sim.World`): `pms.get_visit/get_coverage/find_images`, `nea.upload(key=…)`, `vyne.queue(kind, key=…)` /
  `assert_editable` (raises `HoldWindowClosedError` → 409 `file_departed`), `payer(key).check_status/call_rep(key=…)/receive_records(key=…)`.
  Every call is a `WorldCallLog` row; mutations are idempotent by key; outages raise `WorldUnavailableError(retry_after)`.
- **Routing**: `torch.domain.routing.route_denial(carc, rarc, …)` is the one CARC·RARC → next action function (Denials uses it).
- **SSE**: `torch.events.publish(store, channel, event, data, at)`; `/runs/{id}/events` and `/runs/stream` replay from `run_events`.
- The agents worker built `torch/agents/ports.py` (WorldPort/DomainPort/SchedulerPort); the adapters over the above are the
  coordinator's integration step.
