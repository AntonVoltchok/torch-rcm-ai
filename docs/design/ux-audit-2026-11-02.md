# UX audit — Torch web app

Run 2026-11-02 against the real API, canonical seed, clock Wed 10/28 10:40, as Dana, at 1440×900. Resting screens were read from the live demo stack. The post-click path was watched on a throwaway API and database on spare ports, so demo state was not touched. Primary reader for trade-offs: the evaluator in a five-minute demo (owner's call), then a daily biller. Red-teamed in `docs/design/red-team/challenge-ux-audit-2026-11-02.md`; this version folds that in, and regrades are marked.

## The diagnosis in one paragraph

Every element on screen is the same loudness. Text sits in a 3px band, bold is the default rather than the exception, one blue means nine different things, and the app's most important sentence (agents ran 41 items, 12 came to you) is 12.5px gray under a banner. The data model is excellent and the screens show nearly all of it at once, so a viewer has to read in order to find the next action. The fix is hierarchy and removal, not decoration.

## What is working and must survive

- Evidence cards with real provenance. This is the trust story.
- The money math and the honest "23 of 25" base rates.
- Keyboard model (`J/K/A/E/R/S`, `⇧A`), but as a discoverable layer rather than a permanent footer.
- "root cause: ours" being visibly uncomfortable.
- URL-driven state, and the tiered model.
- Every hard rule in `CLAUDE.md`: no count the server did not compute, tier 3 stays human, money formatting only in the UI, no vendor names beyond the permitted list.

## Principles for the redesign

1. **Whose move is it.** Every claim is waiting on you, an agent, or the payer. Say which, everywhere. In production this is a server-derived field, never client logic.
2. **Truth before hierarchy.** Any number made louder must first reconcile across screens.
3. **One next action on a decision screen.** It sits next to the decision and is the only filled control in view. A blocked item says, as visible text, who can act and why.
4. **Design the after-state.** Every decision shows what is happening, what changed, and what comes next. Failure gets the same care.
5. **Three levels of reading.** Decide (large), justify (normal), audit (quiet). Evidence is justify, so it stays on the page.
6. **A colour means one thing.** Action, agent and money-at-risk get separate hues. Tiers are neutral. Status stays quiet until it demands something.
7. **Say it like a person.** "F. Diaz · crown · Delta needs the PA x-ray", with the claim number kept beside the name. Lead with "23 of 25", not 92%. Gloss Torch's coinages.
8. **The strip stays visible and compressed.** Only what changed or needs you has weight.
9. **Show the agent's work as the headline.** What it did, what it needs, how often this has worked, and which rule stopped it.
10. **Space before borders.**

## Directions

Mixed range as agreed. A's type, colour and contrast repairs are the baseline for all five, so the variations compare ideas rather than skins. Each states which of the demo steps it serves.

- **A. Biller's view (close).** Same information and two-pane layout with real hierarchy. Must prove H4, H5, C1, C3, S1.
- **B. Docked decision (close).** Same identity, decision-first. The bar states exactly what gets touched, and the policy preview sits inline on "always auto-run". Must prove A1, A2, A3, A6.
- **C. Shift brief (restructure).** The empty-selection state becomes the agents' report, and the queue is walked one decision at a time. Must prove H1, H2 and that J/K and Approve 3 survive.
- **D. Whose move (restructure).** A claim-wide state line across rows, Claim and Denials, and Approve 3 visibly moves ownership. Must prove "Denied stays 5" reads without narration.
- **E. Run log (bold).** Replaces Spotlight, which was a costume on C and worsened contrast. The agents' live stream is the primary surface and decisions arrive as blocking prompts: allow once, always allow, hard stop. Must prove R1, R2, the failure path, D9 and A6.
